# AGENTS.md

Guide for AI coding agents (and humans) working in this repo. Read this first, then `CLAUDE.md`.

## What this is

A mortgage calculator in four modules: `frontend/` (TypeScript, Vite), `api/` (the contract: an OpenAPI
file and example files), `backend/` (Python 3.12, FastAPI: all the calculations) and `supabase/` (the
SQL of the one table that stores saved calculations). The plan, the specs and the test scenarios are
in `docs/v2/` (and `docs/v1/` for the first version, which is not edited). Build only according to
`docs/v2/05-plan.md`.

## Commands

```bash
npm install && (cd backend && uv sync)    # once
npm run dev                               # backend on :8000 and frontend on :5173
npm test                                  # frontend and backend tests (run before every commit)
npm run check                             # everything CI runs
```

Definition of done: `npm run check` passes.

## Layout

| Path                                                  | Role                                                                              |
| ----------------------------------------------------- | --------------------------------------------------------------------------------- |
| `frontend/src/api/`                                   | The only code that calls `fetch` (`client.ts`) and the types of the contract      |
| `frontend/src/ui/`                                    | The form, the schedule table and the chart. Thin: no calculations                 |
| `frontend/src/format/`, `identity.ts`                 | Text formatting, the random browser id                                            |
| `backend/app/calc/`                                   | Pure rules: payment, validation, schedule, extra payment. **No input or output**  |
| `backend/app/service.py`                              | Connects validation, calculation and storage                                      |
| `backend/app/repository.py`, `supabase_repository.py` | The storage interface, an in-memory version, the Supabase version                 |
| `backend/app/web/`                                    | The HTTP layer (FastAPI): request shape, status codes, CORS. No calculation rules |
| `api/openapi.json`, `api/examples/`                   | The contract. Generated by `backend/scripts/`, tested from both sides             |
| `supabase/migrations/`                                | SQL. The owner runs it in the Supabase SQL editor                                 |
| `docs/v2/03-test-scenarios.md`                        | Every test by name. `npm run check:scenarios` keeps code and document in step     |

Dependency rules (tested): `frontend` knows the backend only through `api/`; `calc` imports nothing from
the other backend layers; `web` does not import the Supabase code; the browser has no Supabase code.

## Conventions

- Test first, one commit per step. A change to a rule changes the scenario document first.
- Money is whole cents and the rate is whole hundredths of a percent between the modules. No floats.
- `calc` raises `ValueError` for wrong input. `web` turns validation errors into the 422 body of the contract.
- If you change the API, change the code, run `uv run python scripts/export_openapi.py` and
  `uv run python scripts/generate_examples.py` in `backend/`, and check the numbers in the examples
  against `docs/v2/reference-schedule.py` and `reference-extra.py`.
- Style: Prettier for the frontend and docs, ruff for Python. Hooks format staged files.

## Git workflow

- Conventional Commits (`feat(backend): ...`), enforced by a `commit-msg` hook. Subject and every body
  line are at most 100 characters.
- Scopes used: `frontend`, `backend`, `api`, `supabase`, `calc`, `ui`, `deps`.
- Update `CHANGELOG.md` under **Unreleased** for user-visible changes.

## Gotchas

- Husky hooks run on commit. If one fails, fix the cause and make a new commit. Do not use `--no-verify`.
- Never commit secrets. `backend/.env` is ignored. The Supabase secret key goes there and nowhere else.
- `.mcp.json` points at the Supabase project in read-only mode and expects `SUPABASE_ACCESS_TOKEN` in the
  environment. It is for checking the database, not for running the app.
- The differential tests need `git` and `node` and the tag `v1-final`. CI sets `REQUIRE_DIFFERENTIAL=1`.
