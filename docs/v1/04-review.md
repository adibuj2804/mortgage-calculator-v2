# Mortgage calculator V1: Independent review

## How the review was done

- **Reviewer:** a subagent with a fresh context (no memory of writing the plan), given only `01-functional.md`, `02-architecture.md` and `03-test-scenarios.md`, and the review prompt from the assignment (see `prompts.md`, Step 4). It could not modify files.
- **Limit of the "clean context":** the reviewer also saw the git log from its environment (finding 10 comes from that). A subagent is clean of the author's reasoning, not of the repository context.
- **Rounds:** 2. Round 1 reviewed the first drafts of 01 to 03. Round 2 reviewed the revised files (see the bottom of this file).
- **Own review first:** before round 1 the author wrote down their own findings in the same session (8 items, listed in the last section) to compare them with the independent review.

## What the review found that the author did not

The author's own review (same session, written before the independent one):

1. Total interest can be negative, and a 0 % loan can show non-zero interest. (= finding 1)
2. No message for too many decimals or a non-integer term. (= finding 6)
3. A stale result stays on screen after an edit. (= finding 7)
4. Thousands separators typed by the user are not specified. (= finding 5)
5. Parse rules for `1e5`, `+5`, `007` are not specified. (= finding 5)
6. The wording of the loan and term messages is only given by pattern. (partly finding 2)
7. The rounding mode is only in the architecture. (= finding 3)

Seven items (the 0 % interest and the negative interest are one finding), all also found by the reviewer. The reviewer additionally found 10 things the author missed: the missing e2e contract (blocker 2), the non-discriminating tie test (4), the format ambiguity (8), the wrong extension points (9), and findings 11 to 16 (modules contract, layout rule, traceability, untested items, sources, timing).
